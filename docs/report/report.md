# Отчёт о реализации эмулятора процессора

## 1. Лист задания

Разработать программный эмулятор процессора с гарвардской архитектурой, трёхадресными арифметическими командами и знаковыми целыми числами в дополнительном коде. Реализовать перевод пользовательского ассемблера в машинные слова и исполнение этих слов процессором.

Первая программа должна вычислять сумму элементов массива длиной 6–15. Вторая — сумму попарных произведений двух массивов по 10 элементов с использованием длинной арифметики. Обработка выполняется в циклах внутри эмулируемых программ. В методичке второе вычисление называется свёрткой; сдвиг массивов не выполняется.

После каждой команды должны быть доступны регистры общего назначения, аккумулятор, счётчик, PC, IR, флаги и память. Текущая инструкция представляется машинным словом, ассемблером и полями. Команды имеют фиксированную длину, работают со скалярами; обращения к данным выполняются через пересылки. Необходимы непосредственная, регистровая, прямая и косвенно-регистровая адресации.

Основание — раздел 4.1 [исходной методички](../../task/task.md). Принятые параметры модели: данные 16 бит, инструкции 32 бита, 16 регистров, 1024 слова команд и 4096 слов данных. Эти размеры являются проектными решениями.

В исходном тексте встречаются две трактовки первого элемента массива: номер и размер. В реализации принят размер — число следующих элементов, как в уточнении в конце раздела 4.1. Заголовок не участвует в математической сумме. Короткие и пустой массивы используются дополнительно для проверки границ алгоритма суммы.

## 2. Устройство машины

### 2.1. Компоненты

| Компонент | Размер | Назначение |
| --- | --- | --- |
| R0–R15 | 16 × 16 бит | Регистры общего назначения. |
| PC | 16 бит | Адрес следующей команды. |
| IR | 32 бита | Последнее выбранное машинное слово. |
| ZF, NF, CF, OF | Четыре флага по 1 биту | Нуль, знак, перенос/заём, знаковое переполнение. |
| Память команд | 1024 × 32 бит, 4096 байт | Адреса `0x0000…0x03FF`, загрузка машинной программы. |
| Память данных | 4096 × 16 бит, 8192 байта | Адреса `0x0000…0x0FFF`, массивы и результат. |

Объёмы в байтах приведены для сравнения; адресация в машине словная. Единица адреса команд — одна инструкция, единица адреса данных — одно 16-битное слово. После обычной команды PC увеличивается на 1. Одноимённые адреса двух памятей обозначают разные ячейки; программа не может изменять память команд.

R0 — младшая часть аккумулятора, R1 и R2 — следующие части длинного результата, R3 — счётчик цикла по соглашению программ. Все эти регистры имеют обычные права. Аппаратного нулевого регистра нет: R15 обнуляется командами программы суммы. Стек, прерывания и конвейер в модели не реализованы.

### 2.2. Представление данных

Регистры и память содержат битовые шаблоны 0…65535. Для знаковой интерпретации из значений 32768…65535 вычитается 65536; диапазон равен −32768…32767. Длины массивов и адреса трактуются как беззнаковые слова.

Младшее слово длинного числа хранится по меньшему адресу. Пара `lo, hi` представляет `lo + hi × 2¹⁶`, тройка `lo, mid, hi` — `lo + mid × 2¹⁶ + hi × 2³²`. При установленном старшем знаковом бите вычитается соответственно 2³² или 2⁴⁸.

Сумма 15 элементов лежит в пределах −491520…491505 и помещается в 32 бита. Сумма десяти произведений лежит в пределах −10737090560…10737418240: ей недостаточно 32 бит, поэтому используются три слова — 48 бит.

## 3. Система команд

### 3.1. Форматы и декодирование

Все команды имеют длину 32 бита. Бит 31 — старший. Код OP в битах 31…24 определяет операцию и формат. Зарезервированные биты должны быть нулевыми.

| Формат | Поля от старших битов к младшим |
| --- | --- |
| R | OP[31:24], D[23:20], A[19:16], B[15:12], нули[11:0]. |
| S | OP[31:24], D[23:20], A[19:16], n[15:12], нули[11:0]. |
| X | OP[31:24], D[23:20], M[19:16], V[15:0]. |
| J | OP[31:24], нули[23:16], T[15:0]. |
| H | Все 32 бита равны нулю. |

D, A, B — номера регистров 0…15. D обозначает получателя, кроме ST, где это источник; CMP не записывает регистр и требует D=0. В S поле n задаёт сдвиг 0…15. T — абсолютный адрес перехода 0…1023; старшие шесть бит T нулевые.

| M | Допустимые команды | Значение V и способ адресации |
| --- | --- | --- |
| 0 | MOV | Номер регистра в младших четырёх битах, остальные нулевые; регистровая. |
| 1 | MOV | 16-битная константа; непосредственная. |
| 2 | LD, ST | Адрес 0…4095, старшие четыре бита нулевые; прямая. |
| 3 | LD, ST | Номер регистра адреса в младших четырёх битах; косвенно-регистровая. |

Примеры: `MOV R4, 0x0101`, `MOV R5, R4`, `LD R3, [0x0100]`, `LD R6, [R4]`. Получатель арифметической команды и оба источника задаются явно: `ADD R0, R1, R2`. Источники читаются до записи получателя, поэтому совпадающие регистры допустимы.

Декодер извлекает OP, выбирает формат, проверяет режим и резерв, затем возвращает операнды и ассемблерное представление. Например, `01410101` разбирается как OP=01, D=4, M=1, V=0101 — `MOV R4, 0x0101`; `10012000` — OP=10, D=0, A=1, B=2 — `ADD R0, R1, R2`. Неизвестный OP и ненулевой резерв считаются ошибками.

### 3.2. Операции

`u(x)` — сырые 16 бит, `s(x)` — их знаковое значение, `word(t) = t mod 65536` с результатом `0…65535`. `p = s(Ra) × s(Rb)` — точное знаковое 32-битное произведение. В колонке флагов «сохранить» означает сохранить все четыре.

| `OP` | Формат | Ассемблер | Действие | Флаги |
| --- | --- | --- | --- | --- |
| `00` | H | `HALT` | Остановить выполнение. | Сохранить |
| `01` | X | `MOV Rd, value` / `MOV Rd, Rs` | Записать значение/копию регистра. | Сохранить |
| `02` | X | `LD Rd, [address]` / `LD Rd, [Rs]` | Прочитать одно слово данных. | Сохранить |
| `03` | X | `ST [address], Rs` / `ST [Ra], Rs` | Записать одно слово данных. | Сохранить |
| `10` | R | `ADD Rd, Ra, Rb` | `Rd ← word(u(Ra) + u(Rb))`. | Сложение |
| `11` | R | `ADC Rd, Ra, Rb` | `Rd ← word(u(Ra) + u(Rb) + CFвх)`. | Сложение с переносом |
| `12` | R | `SUB Rd, Ra, Rb` | `Rd ← word(u(Ra) − u(Rb))`. | Вычитание |
| `13` | R | `MULLO Rd, Ra, Rb` | `Rd ← word(p)`. | Умножение |
| `14` | R | `MULHI Rd, Ra, Rb` | `Rd ← word(floor(p / 65536))`. | Умножение |
| `15` | S | `SAR Rd, Ra, n` | `Rd ← word(floor(s(Ra) / 2ⁿ))`, с расширением знака. | Сдвиг |
| `16` | R | `AND Rd, Ra, Rb` | Побитовое И. | Логика |
| `17` | R | `OR Rd, Ra, Rb` | Побитовое ИЛИ. | Логика |
| `18` | R | `XOR Rd, Ra, Rb` | Побитовое исключающее ИЛИ. | Логика |
| `19` | R | `CMP Ra, Rb` | Флаги вычитания, без записи результата. | Вычитание |
| `20` | J | `JMP target` | `PC ← target`. | Сохранить |
| `21` | J | `JZ target` | Если `ZF = 1`, `PC ← target`, иначе `PC ← PC + 1`. | Сохранить |
| `22` | J | `JNZ target` | Если `ZF = 0`, `PC ← target`, иначе `PC ← PC + 1`. | Сохранить |

Коды `OP` в таблице шестнадцатеричные. Любой неуказанный код недопустим. `MULLO` и `MULHI` независимо вычисляют части одного произведения: между ними нужно сохранить оба множителя. Они не записывают соседние регистры неявно. Пересылки и переходы естественно имеют меньше трёх операндов; вычислительные команды явно задают результат и два входа.

### 3.3. Флаги

Для АЛУ `ZF = 1`, когда записываемое 16-битное слово равно нулю; `NF` равен его биту 15. Для `CMP` используется отброшенный результат вычитания. Исключение: `SAR` с нулевым сдвигом копирует источник и сохраняет **все** флаги.

| Операция | `CF` | `OF` |
| --- | --- | --- |
| `ADD`, `ADC` | `1`, если точная беззнаковая сумма больше `65535`. Для `ADC` учитывается входной перенос. | `1`, если `s(Ra) + s(Rb) + c` вне `−32768…32767`, где `c = CFвх` только для `ADC`, иначе 0. |
| `SUB`, `CMP` | `1`, если `u(Ra) < u(Rb)` — был заём. | `1`, если точная знаковая разность вне `−32768…32767`. |
| `MULLO`, `MULHI` | Оба флага равны `1`, если полное `p` не помещается в знаковые 16 бит, иначе `0`. | То же условие, независимо от выбранной половины. |
| `SAR`, `n > 0` | Бит `n − 1` исходного слова. | `0` |
| `AND`, `OR`, `XOR` | `0` | `0` |

Переполнение не останавливает CPU: результат ограничивается 16 битами, состояние отражается флагами. `CF` и `OF` различаются: `0xFFFF + 1 → 0` даёт `CF=1, OF=0`; `0x7FFF + 1 → 0x8000` даёт `CF=0, OF=1`.

В цепочке `ADD` → `ADC` → `ADC` каждая следующая команда использует перенос предыдущей. Между ними нельзя ставить команды, изменяющие флаги. Итоговые `ZF`/`NF` описывают последнее слово, а не всё длинное число; проверка многословного нуля требует проверки всех его слов.

## 4. Программная реализация

### 4.1. Разделение модулей

| Модуль | Реализация |
| --- | --- |
| `src/core/` | Система команд, кодек, АЛУ, память, состояние CPU, загрузка, шаг и ограниченный запуск. |
| `src/assembler/` | Разбор строк и операндов, два прохода для меток, диагностика, машинный образ и карта строк. |
| `src/programs/` | Исходники и данные примеров, чтение готового многословного результата. |
| `src/ui/model/` | Сеанс исполнения, ввод данных и отменяемый планировщик. |
| `src/ui/components/` | Редактор, регистры, поля команды, память и результат. |
| `website/` | Документация VitePress с поиском и темами. |

Модули CPU и ассемблера написаны на TypeScript без зависимости от DOM или React. Интерфейс реализован на React, сборка — Vite. Данные CPU хранятся в `Uint16Array`, инструкции — в `Uint32Array`; результаты АЛУ ограничиваются разрядностью явно. Операции АЛУ используют number: произведение двух 16-битных чисел представимо точно. BigInt используется для разбора литералов, независимого эталона и отображения готового многословного результата. Он не заменяет циклы и цепочки команд длинной арифметики.

Путь программы: текст → ассемблер → 32-битные слова → память команд → декодирование → `step()` → снимок состояния. Исходные строки используются только редактором и диагностикой, но не механизмом исполнения.

### 4.2. Ассемблер и загрузка

Ассемблер допускает одну команду на строку, метки, комментарии после `;`, десятичные и hex-литералы. Регистры и команды нечувствительны к регистру букв, метки — чувствительны. Первый проход определяет адреса меток, второй проверяет операнды и кодирует команды общим кодеком. Неизвестные команды, неверные операнды, диапазоны и метки дают русскую диагностику со строкой и позицией. Директивы данных и выражения не поддерживаются.

Результат сборки содержит машинные слова, точку входа 0, таблицу меток и карту исходных строк. Начальные данные вводятся отдельно в форме `адрес: значение, значение`. Загрузчик до изменения машины проверяет весь образ: размер программы, точку входа, диапазоны данных и уникальность адресов. Ошибочная сборка или загрузка сохраняет прежнюю машину.

### 4.3. Исполнение и ошибки

Один `step()` проверяет PC, выбирает слово в IR, декодирует команду, читает операнды, проверяет адреса и вычисляет эффекты. Записи, флаги и следующий PC применяются только после успешных проверок. При HALT процессор переходит в `halted`; последующие шаги ничего не меняют.

При ошибке выполнения состояние становится `faulted`; регистры, данные, PC и число успешных шагов сохраняются. IR содержит проблемное слово, если выборка состоялась. При ошибке выборки сохраняется прежний IR. Ошибка включает код, адрес и сообщение. Контролируются выход за физические границы памяти, выборка из незагруженной части программы, неверные OP и кодировка.

Интерфейс вызывает тот же `step()` по таймеру. Медленные режимы выполняют по одной команде, быстрый — до 250 за порцию. Пауза отменяет следующий вызов; лимит по умолчанию 100000 команд относится к одному запуску и сохраняет состояние для продолжения. Сброс восстанавливает последний загруженный образ. После редактирования требуется новая сборка. В быстром режиме экран показывает состояние после порции; для наблюдения каждой инструкции служит пошаговый режим.

В интерфейсе доступны все регистры и флаги, адрес выбранной команды, IR, её поля и ассемблер, следующий PC, две памяти и переход к исходной строке. Числа представлены в hex и знаковом decimal. Начальные данные и исходник не сохраняются после перезагрузки страницы; сохраняется только тема.

## 5. Программы массивов

### 5.1. Размещение данных

| Адрес | Содержимое |
| --- | --- |
| `0x0100` | Длина A без заголовка. |
| `0x0101…0x010F` | Элементы A; сумма допускает до 15 элементов. |
| `0x0200` | Длина B. |
| `0x0201…0x020A` | 10 элементов B для свёртки. |
| `0x0300`, `0x0301` | Младшее и старшее слова суммы. |
| `0x0300…0x0302` | Младшее, среднее и старшее слова свёртки. |
| `0x0303` | Статус свёртки: 0 — успех, 1 — неверная длина. |

Обе программы загружаются независимо с адреса команд 0. Неуказанные ячейки данных равны нулю. Длина не входит в вычисление; отрицательные элементы перед загрузкой преобразуются в дополнительный код.

### 5.2. Сумма массива: алгоритм и ассемблер

Аккумулятор — R1:R0, счётчик — R3, указатель — R4. Для каждого элемента R6 команда SAR формирует расширение знака R7. Затем ADD складывает младшие слова, ADC — старшие с переносом. SAR выполняется до ADD, чтобы не затереть перенос. После обновления указателя SUB уменьшает счётчик; JNZ использует именно полученный флаг нуля.

Предусловие программы — корректная длина 0…15. Основные данные имеют длину 10, пустой массив используется как граничный тест. Произвольный повреждённый заголовок длины программа суммы не валидирует; CPU проверяет фактические обращения к памяти.

<!-- report:sum-source:start -->
```asm
    MOV R0, 0
    MOV R1, 0
    MOV R15, 0
    MOV R11, 1
    MOV R4, 0x0101
    LD R3, [0x0100]
    CMP R3, R15
    JZ done
loop:
    LD R6, [R4]
    SAR R7, R6, 15       ; расширить знак до старшего слова
    ADD R0, R0, R6
    ADC R1, R1, R7       ; перенос от младшего слова
    ADD R4, R4, R11
    SUB R3, R3, R11
    JNZ loop            ; флаг нуля от уменьшения счётчика
done:
    ST [0x0300], R0
    ST [0x0301], R1
    HALT
```
<!-- report:sum-source:end -->

### 5.4. Свёртка: алгоритм и ассемблер

Аккумулятор — R2:R1:R0, указатели — R4/R5, счётчик — R3. Заголовки обоих массивов должны равняться 10. Если любой заголовок неверен, программа пишет статус 1 и останавливается без изменения трёх слов результата.

Для каждой пары MULLO и MULHI вычисляют R9:R8 из неизменённых множителей R6/R7. SAR расширяет знак произведения в R10. Цепочка ADD → ADC → ADC прибавляет произведение к 48-битному аккумулятору. Например, произведение −1 представлено перед сложением как `FFFF FFFF FFFF`; положительный перенос после него проходит через оба старших слова.


## 6. Проверка реализации

### 6.1. Методы

Кодек проверяется на вручную заданных машинных словах, неверных режимах и резервных битах. Тесты АЛУ различают перенос и знаковое переполнение, проверяют крайние числа, умножение и сдвиги. CPU проверяется на границах памяти, переходах, атомарности ошибок, остановке и сбросе. Ассемблер — на метках, адресации, диапазонах и диагностике.

Программы массивов исполняются через ассемблер и машинную память. Ожидаемые суммы вычисляются независимой арифметикой BigInt. Сравниваются слова памяти, регистры аккумулятора, счётчики и указатели, количество шагов, неизменность входов и повторный запуск. Проверяется каждая частичная сумма, знак произведения и перенос между двумя старшими словами. Дополнительно используются 64 воспроизводимых случайных набора для каждой программы.

Браузерные сценарии проверяют шаги, запуск, паузу, лимит, сброс, ошибки сборки и CPU, границы памяти, отображение многословных результатов, светлую/тёмную темы и ширины 320, 390 и 1440 пикселей.

## 7. Воспроизведение и демонстрация

Для локальной работы необходимы Node.js 22.12+ и npm:

```bash
npm ci
npm run check
npm run arrays:demo
npx playwright install chromium
npm run test:browser
npm run dev
```

`check` проверяет типы, модули и сборки документации/приложения. CLI выводит оба машинных листинга и сверяет результаты. Приложение открывается по адресу Vite с путём `/emulator/app/`. Пошаговые сценарии с ожидаемыми состояниями приведены в [протоколе демонстрации](demonstration.md).

Для краткой демонстрации достаточно выполнить сумму массива, затем свёртку максимальных по модулю отрицательных значений и сравнить панель результата с памятью. После этого изменить длину B на 9 и убедиться в статусе ошибки без записи результата. Пауза между ADD и ADC демонстрирует сохранение переноса до продолжения.

## 8. Заключение

Реализован эмулятор гарвардского процессора с фиксированными 32-битными командами и знаковыми 16-битными данными. Пользовательский ассемблер проходит полный путь до машинного исполнения; состояние обязательных компонентов доступно после каждого шага.

Обе программы обрабатывают массивы в циклах CPU. Сумма использует 32-битный аккумулятор, свёртка — 48-битный. Проверки подтверждают корректность знакового расширения, переносов, граничных значений, обработки неверных длин свёртки и повторного запуска. Реализация позволяет наблюдать разницу между машинной командой, состоянием отдельного слова и итоговым многословным числом.

Область реализации ограничена описанной машиной: нет стека, прерываний, дополнительных архитектур, директив ассемблера и сохранения пользовательских программ между перезагрузками. Программа суммы предполагает корректный заголовок длины. Дальнейшие изменения этих возможностей требуют отдельного изменения контракта и проверок.
