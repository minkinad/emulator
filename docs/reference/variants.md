# Сравнение вариантов архитектуры

Справочный разбор 16 вариантов из [методички, раздел 4.1](../../task/task.md). Сравнение описывает архитектурные различия; оно не означает, что эмулятор поддерживает переключение между всеми конфигурациями. Реализованная модель описана в [спецификации CPU](../architecture/cpu.md).

## Обозначения

- **ФН** — архитектура фон Неймана: общая память команд и данных.
- **Г** — гарвардская архитектура: раздельные адресные пространства.
- **Одноадресная** — один явный операнд; второй операнд и результат связаны с аккумулятором.
- **Двухадресная** — результат заменяет один из двух явных операндов.
- **Трёхадресная** — получатель и два источника задаются явно.
- **Безадресная** — операнды находятся на вершине регистрового стека.

Адресность инструкции и способ адресации операнда — разные свойства. Например, трёхадресная арифметическая инструкция может использовать только регистровые операнды.

## Особенности семейств

### Одноадресные: 1, 5, 9, 13

Аккумулятор упрощает формат команды, но создаёт неявную зависимость между операциями. Отдельные регистры или ячейки требуются для указателей, счётчика и промежуточных результатов. При ограничении доступа к памяти пересылками арифметика выполняется после загрузки операнда в регистр.

### Двухадресные: 2, 6, 10, 14

Получатель совпадает с одним из источников. Это уменьшает число адресных полей, но требует сохранять значения, которые понадобятся после операции. Особенно чувствительны к перезаписи множители и части длинного результата.

### Трёхадресные: 3, 7, 11, 15

Отдельное поле получателя делает поток данных явным. Кодирование должно вмещать три регистра и дополнительные поля в фиксированную длину. Разрядность данных, ширина адресов и размер инструкции могут различаться.

### Безадресные: 4, 8, 12, 16

Короткие инструкции используют стек. Основная сложность связана с порядком операндов, перестановками, глубиной стека и частями длинного числа. Для каждой операции требуется однозначно определённый эффект над стеком и проверка его границ.

## Память и длинная арифметика

В общей памяти код и данные требуют согласованной карты размещения. В гарвардской архитектуре одинаковый числовой адрес может обозначать разные ячейки: одну в памяти команд, другую в памяти данных.

Ширина накопителя определяется суммой произведений, а не одним произведением. Например, `10 × (−32768) × (−32768) = 10737418240` превышает знаковый 32-битный диапазон. Три 16-битных слова дают достаточный запас. Для отрицательных произведений требуется расширение знака, для всех многословных сложений — передача переноса.

Примеры циклов и контрольных результатов приведены в [алгоритмах массивов](../architecture/programs.md).

## Ограничения исходного материала

Таблица потеряла объединённые ячейки при конвертации. Для № 8 расходится знаковость: текст относит его к беззнаковым, положение подписей допускает знаковую свёртку. У № 16 указана необычная комбинация первой задачи и памяти. Эти строки требуют сверки с оригиналом.

Для первого массива встречаются диапазоны 6–15 и 7–15; длина 10 удовлетворяет обоим. Заголовок массива трактуется как число последующих элементов по подробному пояснению раздела 4.1. В стековом примере `JNZ` имеет противоречивое описание; в реализованном CPU это переход при `ZF = 0`.
