# Ассемблер

Ассемблер переводит текст в 32-битные машинные слова по [спецификации CPU](cpu.md). Первый проход определяет адреса меток, второй проверяет операнды и кодирует команды через общий кодек. Сборка не загружает программу и не изменяет состояние процессора.

## Запуск примера

```bash
npm ci
npm run assembler:demo
```

Пример [countdown.asm](../../examples/assembly/countdown.asm) вычисляет `3 + 2 + 1` в цикле. Команда выводит машинный листинг с исходными строками и запускает его на CPU. Ожидаемый результат — 6 по адресу данных `0x0300`, 14 выполненных команд.

## Синтаксис

На строке располагаются необязательная метка и одна инструкция. Операнды разделяются запятыми, комментарии начинаются с `;`. Пустые строки и отдельные строки с метками разрешены. Поддерживаются окончания строк LF, CRLF и CR.

```asm
    MOV R0, 0
    MOV R1, 3
    MOV R2, 1
loop:
    ADD R0, R0, R1
    SUB R1, R1, R2
    JNZ loop
    ST [0x0300], R0
    HALT
```

Имена команд и регистров нечувствительны к регистру букв: `mov r0, 1` эквивалентно `MOV R0, 1`. Регистры обозначаются `R0…R15`, без ведущих нулей.

### Операнды и адресация

| Запись | Значение |
| --- | --- |
| `MOV R0, -1` | Знаковый десятичный литерал в пределах `−32768…32767`. |
| `MOV R0, +12` | Положительный десятичный литерал; знак `+` необязателен. |
| `MOV R0, 0xFFFF` | Сырые 16 бит; hex-литералы `0x0…0xFFFF`, префикс также может быть `0X`. |
| `MOV R0, R1` | Копия регистра. |
| `LD R0, [256]` | Прямой адрес памяти данных `0…4095`. |
| `LD R0, [R4]` | Адрес памяти данных берётся из регистра; пробелы внутри скобок допустимы. |
| `ST [0x0300], R0` | Запись в память: получатель стоит первым. |
| `ADD R0, R1, R2` | Арифметика над регистрами; константы сначала загружаются через `MOV`. |
| `SAR R0, R1, 15` | Арифметический сдвиг на непосредственное число позиций `0…15`. |
| `JNZ loop` | Абсолютный переход к метке. |
| `JMP 0x03FF` | Абсолютный адрес команд `0…1023`. |

Адреса и число позиций сдвига записываются без знака, в десятичном или hex-виде. Знаки перед hex запрещены. Десятичное `65535` не является знаковым литералом `MOV`; для такого битового шаблона используется `0xFFFF` или `-1`. Выражения, директивы данных, псевдокоманды и пересылки память → память не поддерживаются.

### Метки

Имя соответствует `[A-Za-z_][A-Za-z0-9_]*`, завершается двоеточием и чувствительно к регистру букв. `loop` и `Loop` — разные метки. На строке допускается одна метка; несколько отдельных строк с метками могут обозначать одну следующую инструкцию. После последней метки обязательно должна быть инструкция.

Метки применяются только в переходах. Повторное определение и ссылка на неизвестное имя вызывают ошибку. Команды размещаются с адреса 0, одна команда занимает одну ячейку; пустые строки, комментарии и метки не расходуют память. Максимум — 1024 инструкции.

Числовой переход в физически допустимую, но незагруженную ячейку можно собрать: CPU обнаружит ошибку при последующей выборке. Метка всегда указывает на существующую команду исходника.

## API

После `npm run build`:

```js
import { assemble, AssemblyError } from './dist/assembler/index.js';
import { Cpu, run } from './dist/core/index.js';

try {
  const result = assemble('LD R0, [256]\nHALT');
  const cpu = new Cpu({
    ...result.image,
    data: [{ address: 256, value: 42 }],
  });
  console.log(run(cpu).state.registers[0]); // 42
  console.log(result.sourceMap[0].line);  // 1
} catch (error) {
  if (!(error instanceof AssemblyError)) throw error;
  console.error(error.message);
}
```

`assemble(source)` возвращает:

| Поле | Содержимое |
| --- | --- |
| `image` | `ProgramImage`: машинные `instructions`, `entryPoint = 0`, пустой массив `data`. Данные можно добавить перед загрузкой. |
| `labels` | `ReadonlyMap<string, number>`: имена меток и адреса команд. |
| `sourceMap` | По одной записи на инструкцию: `address`, `line`, `column`, `text` исходной строки. |

Строки и позиции нумеруются с 1. Позиция указывает на начало команды или ошибочного операнда и измеряется в кодовых единицах UTF-16; табуляция считается одним символом. Адреса команд нумеруются с 0. Карта строк предназначена для подсветки и диагностики, CPU её не использует.

## Диагностика

Сборка останавливается на обнаруженной ошибке и бросает `AssemblyError`; частичный образ не возвращается. Сначала проверяется структура всего исходника, затем операнды, поэтому структурная ошибка ниже по тексту может быть сообщена раньше ошибки операнда выше.

`error.message` содержит русский текст с номером строки и позицией. `error.diagnostic` предоставляет отдельные поля `code`, `line`, `column`, `message`.

| Код | Причина |
| --- | --- |
| `EMPTY_PROGRAM` | Нет ни одной инструкции. |
| `PROGRAM_TOO_LARGE` | Превышены 1024 инструкции. |
| `INVALID_LABEL` | Неверное имя, несколько меток на строке или метка после последней инструкции. |
| `DUPLICATE_LABEL` | Повторное определение имени. |
| `UNDEFINED_LABEL` | Переход к неизвестной метке. |
| `UNKNOWN_INSTRUCTION` | Неизвестная команда или неподдерживаемая директива. |
| `OPERAND_COUNT` | Неверное число операндов, пропущенная запятая или пустой операнд. |
| `INVALID_REGISTER` | Ожидался регистр `R0…R15`. |
| `INVALID_LITERAL` | Неверная запись числа или неподдерживаемое выражение. |
| `INVALID_OPERAND` | Неверная запись адреса памяти. |
| `OUT_OF_RANGE` | Число, адрес или сдвиг вне допустимого диапазона. |

Например, `MOV R0, 32768` даёт `OUT_OF_RANGE`, строка 1, позиция 9. Ошибки выполнения — выход косвенного адреса за границы, выборка вне программы — относятся к [ядру CPU](core-api.md), а не к сборке.
