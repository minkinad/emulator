# Использование ядра CPU

Ядро реализовано на TypeScript в `src/core/`. Оно исполняет машинные слова по [спецификации](cpu.md), не зависит от браузера и не разбирает ассемблерные строки. Публичная точка входа — `src/core/index.ts`, после сборки — `dist/core/index.js`.

## Установка и проверка

Из корня проекта, Node.js 22.12+:

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run core:demo
```

`core:demo` сначала собирает ядро, затем запускает [пример](../../examples/machine/add.mjs) с вручную записанной программой `2 + 3`. На каждом шаге выводятся адрес, машинное слово, декодированная команда, регистры и следующий `PC`. Итог — `R0 = 5`, `PC = 4`, состояние `halted`.

`npm run check` объединяет проверку типов, модульные тесты, сборку библиотеки, приложения и документации. Браузерные сценарии запускаются отдельно через `npm run test:browser`.

Конфигурация TypeScript включает строгую проверку типов и проверку доступа по индексу; основной проект не подключает типы DOM или Node.js. Назначение этих параметров описано в [справочнике TSConfig](https://www.typescriptlang.org/tsconfig/). Node.js используется в тестах и демонстрационном скрипте, но не в самом ядре.

## Минимальный запуск

После `npm run build`, из корня проекта в ESM-скрипте:

```js
import { Cpu, run } from './dist/core/index.js';

const cpu = new Cpu({
  instructions: [0x01110002, 0x01210003, 0x10012000, 0x00000000],
  entryPoint: 0,
  data: [],
});

const first = cpu.step();
console.log(first.state.decoded.assembly); // MOV R1, 0x0002
console.log(first.state.pc);               // 1

const result = run(cpu, 100);
console.log(result.reason);               // halted
console.log(result.state.registers[0]);   // 5
console.log(result.executedSteps);        // 3 команды этого запуска
console.log(result.state.steps);          // 4 команды после загрузки
```

## Образ программы и состояние

Образ `ProgramImage` содержит три обязательных поля:

- `instructions`: обычный массив сырых 32-битных слов, от 1 до 1024;
- `entryPoint`: адрес внутри загруженного массива команд;
- `data`: список `{ address, value }`, где адрес — `0…4095`, слово — `0…65535`. Повторные адреса запрещены.

Данные со знаком переводятся в сырые слова перед загрузкой: `−1` записывается как `65535` или `0xFFFF`. Неизвестный opcode допустим внутри образа, чтобы ошибку можно было наблюдать при выполнении; значения вне разрядности отвергаются загрузчиком.

| API | Результат |
| --- | --- |
| `new Cpu(image)` | Загруженная и обнулённая машина в состоянии `ready`. |
| `new Cpu()` | Пустая машина; попытка шага даёт ошибку выборки. |
| `cpu.load(image)` | Полная проверка и замена образа, затем исходный снимок. Ошибка бросает `MachineError` и сохраняет предыдущую машину. |
| `cpu.reset()` | Восстановление сохранённого образа, регистров, памяти, флагов и счётчика; возвращает снимок. Для пустой машины восстанавливает пустое состояние. |
| `cpu.snapshot()` | Отделённый снимок регистров, флагов, `PC`, `IR`, адреса выборки, декодированной команды, статуса, ошибки и счётчика. |
| `cpu.readData(address)` | Одно слово физической памяти данных. |
| `cpu.readInstruction(address)` | Одно слово физической памяти команд, включая нулевые незагруженные ячейки; `step()` дополнительно проверяет наличие загруженной команды. |
| `cpu.memory()` | Копии обоих блоков памяти для просмотра. |
| `cpu.step()` | Одна инструкция, новый снимок и список изменений регистров/данных. |
| `run(cpu, maxSteps)` | Ограниченное синхронное исполнение через тот же `step()`. |

Типы снимков объявлены `readonly`, а объекты, вложенные поля команды и массивы отделены от состояния CPU. Изменение снимка или исходного образа из JavaScript не меняет машину и образ для сброса. Память не копируется на каждом шаге целиком: для этого есть отдельный `memory()`.

## Результат одного шага

`StepResult` содержит `executed`, `state` и `writes`.

`executed = true` означает успешно выполненную инструкцию, включая `HALT`; увеличивается `state.steps`. При ошибке или повторном шаге остановленной машины `executed = false`. `writes` содержит только фактически изменившиеся слова: `{ kind: 'register' | 'data', address, before, after }`. Изменения `PC`, `IR` и флагов доступны в снимке.

В `state.decoded` находятся машинное `word`, `format`, `fields`, структурированная `instruction` и строка `assembly`. При ошибке декодирования это поле равно `null`, а `IR` содержит неверное слово. При ошибке выборки сохраняются предыдущие `IR`, адрес выборки и декодированная команда; адрес неудачной выборки находится в `state.fault.address`.

Флаги API: `zf`, `nf`, `cf`, `of`, значения — `boolean`; интерфейс может отображать их как `ZF`, `NF`, `CF`, `OF` и `0/1`. Адрес исполненной команды хранится в `instructionAddress`, следующий адрес — в `pc`. До первой выборки `instructionAddress = null`.

## Кодек и ошибки

```js
import { encode, decode } from './dist/core/index.js';

const word = encode({ op: 'ADD', d: 0, a: 1, b: 2 });
console.log(word.toString(16));      // 10012000
console.log(decode(word).assembly); // ADD R0, R1, R2
```

`encode` получает уже разобранные операнды; значения должны соответствовать полям формата, а не ассемблерному синтаксису. Например, для `MOV` значения `mode` — `register` или `immediate`, для `LD`/`ST` — `direct` или `indirect`. Отрицательный непосредственный операнд здесь уже должен быть преобразован в 16 бит. Резервные биты, адреса и регистры проверяются до исполнения. Разбор текста и меток выполняет [ассемблер](assembler.md).

`MachineError` содержит русский `message` и стабильный `code`. `encode`, `decode`, загрузка и чтение памяти вне границ бросают исключения. `step()` преобразует ожидаемую машинную ошибку в состояние `faulted`; дальнейшие шаги ничего не меняют. Исправление требует загрузки или сброса. Неожиданная ошибка реализации не маскируется под машинную.

`run()` возвращает причину `halted`, `faulted` или `limit`, число выполненных команд **этого запуска** и снимок. Лимит по умолчанию — 100000; достижение лимита оставляет CPU в `ready`, поэтому выполнение можно продолжить. Неверный лимит вызывает `INVALID_STEP_LIMIT`. Этот синхронный помощник предназначен для тестов и CLI; браузерный интерфейс вызывает `step()` порциями и отдавать управление браузеру.

## Что уже проверяется

В `tests/core/` находятся тесты ручных машинных кодов, всех команд и режимов, резервных полей, флагов и переносов, знакового умножения, границ памяти, переходов, атомарности ошибок, сброса и ограниченного выполнения. Арифметика дополнительно сверяется с независимым `bigint`-эталоном на граничных и 2000 воспроизводимых случайных парах слов.

Это проверки ядра и коротких машинных программ. Для [листингов массивов](programs.md) проверяются сборка и адреса переходов; полные интеграционные проверки запланированы.
