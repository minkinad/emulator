# Публикация сайта и приложения

Сайт документации: [minkinad.github.io/emulator](https://minkinad.github.io/emulator/). Публикация выполняется workflow [GitHub Pages](../../.github/workflows/pages.yml).

## Как устроен сайт

Сайт собран на VitePress. Главная страница содержит схему процессора и маршрут работы, остальные страницы — документацию из репозитория. Доступны светлая и тёмная темы, локальный поиск, мобильная навигация и оглавление страницы. Для поиска не нужны внешний сервис или ключи.

| Что редактировать | Где появится |
| --- | --- |
| `README.md` | Начало работы |
| `docs/architecture/cpu.md` | Спецификация процессора |
| `docs/architecture/assembler.md` | Синтаксис и API ассемблера |
| `docs/architecture/core-api.md` | Использование ядра |
| `docs/architecture/programs.md` | Алгоритмы массивов |
| `docs/project/application.md` | Работа с приложением |
| `docs/project/structure.md` | Структура проекта |
| `docs/reference/variants.md` | Сравнение вариантов |
| `docs/project/implementation.md` | План развития |
| `.github/CONTRIBUTING.md` | Участие в разработке |
| `CHANGELOG.md` | История изменений |
| `docs/project/publishing.md` | Эта страница |
| `docs/report/report.md` | Отчёт о реализации |
| `docs/report/demonstration.md` | Протокол демонстрации и экспорт PDF |
| `website/index.md` | Главная страница |

При запуске и сборке `scripts/docs/prepare.mjs` создаёт страницы в `website/guide/`, `website/project/` и `website/report/`, преобразуя относительные ссылки для сайта. Эти каталоги генерируются и исключены из Git. Редактировать нужно исходные Markdown-файлы, а не копии. Во время локальной разработки изменения исходников автоматически обновляют страницы. Служебный `AGENTS.md` остаётся в репозитории и не включается в сайт, поиск или карту сайта. Перед генерацией старые копии страниц удаляются из этих трёх каталогов.

Ссылки на методичку ведут к исходному файлу в GitHub: конвертация содержит повреждённые ссылки на иллюстрации, поэтому её не включаем в сборку сайта. Исходники задания остаются без изменений.

## Локальный запуск

Нужен Node.js 22.12 или новее и npm. Из корня репозитория:

```bash
npm ci
npm run docs:dev
```

Откройте адрес, напечатанный VitePress, с путём `/emulator/`. Эта команда запускает сайт документации; ядро демонстрируется отдельно через `npm run core:demo`.

Проверка производственной сборки:

```bash
npm run site:build
npm run docs:preview
```

Полная сборка добавляет приложение в `/emulator/app/`: `scripts/site/prepare.mjs` копирует `dist/app/` в `website/.vitepress/dist/app/`. В preview доступны документация и приложение. Команда `docs:build` собирает только документацию и очищает предыдущий артефакт; для публикации используется `site:build`.

Путь `/emulator/` задан в `website/.vitepress/config.mts` и соответствует имени репозитория на GitHub Pages. ЧПУ без расширений выключены: страницы публикуются как `.html`, чтобы прямое открытие вложенной страницы работало на статическом хостинге.

## GitHub Actions

1. В pull request workflow устанавливает зависимости через `npm ci`, собирает сайт и экспортирует PDF отчёта в Chromium. Ошибочные внутренние ссылки останавливают сборку.
2. После push в `main` или ручного запуска из `main` workflow собирает сайт, подготавливает Pages и загружает артефакт.
3. Отдельная задача публикует артефакт в окружение `github-pages`. Одновременные публикации выполняются последовательно.

Pull request не публикует сайт. Задача сборки имеет право чтения репозитория, а право записи в Pages и OIDC выдаётся только задаче публикации. Используются стандартные Actions, закреплённые на SHA; секрет с персональным токеном для workflow не требуется.

При первоначальной настройке в **Settings → Pages → Build and deployment → Source** должен быть выбран **GitHub Actions**. Настройка соответствует [официальной документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) и [руководству VitePress](https://vitepress.dev/guide/deploy).

## Оформление

Сайт оформлен в стиле SwiftUI: системная типографика, синий акцент, скруглённые карточки, полупрозрачная навигация и согласованные светлая/тёмная темы. Это веб-тема на CSS и Vue; SwiftUI как библиотека в сайте не используется. Настройка уменьшения движения в системе отключает переходы оформления.

Общие цвета, типографика, адаптивные стили и оформление таблиц находятся в `website/.vitepress/theme/style.css`. Схема процессора и этапы на главной — Vue-компоненты в той же папке. Схема концептуальная: она не исполняет команды и не подменяет интерфейс эмулятора.

Навигация, русские подписи, поиск и ссылки на редактирование исходников настроены в `website/.vitepress/config.mts`. Сборка находится в `website/.vitepress/dist/` и не коммитится.

## Публикация отчёта

Страница отчёта доступна по `/emulator/report/report.html`, протокол — `/emulator/report/demonstration.html`. При сборке документации `report:check` проверяет полные ассемблерные и машинные листинги отчёта. `AGENTS.md` и персональный титульный лист не публикуются.

В Pages workflow после `site:build` устанавливается Chromium Playwright и запускается `node scripts/report/pdf.mjs`. Скрипт обслуживает только локальную сборку на временном loopback-порту, печатает страницу A4, закрывает браузер и сервер. PDF записывается в `dist/report/emulator-report.pdf` и добавляется в артефакт сайта по `/emulator/reports/emulator-report.pdf`. Ссылки внутри PDF ведут на публичный сайт, а не временный локальный адрес. Экспорт не публикует файлы самостоятельно.

Для отдельной локальной сборки PDF предусмотрен `npm run report:pdf`; сначала нужен `npx playwright install chromium`. Совместимый установленный Chromium можно задать переменной `REPORT_CHROMIUM_PATH`. `site:build` создаёт HTML-сайт и приложение; PDF добавляется отдельным шагом. Печатные стили в `website/.vitepress/theme/report.css` применяются только к отчёту.
