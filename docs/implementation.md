# Поэтапная реализация

Цель — работающий эмулятор **варианта 7**: трёхадресная гарвардская машина со знаковыми числами, программой суммы и свёрткой двух массивов по 10 элементов.

## Как проходит этап

1. Выполнить ограниченный объём работы и соответствующие проверки.
2. Записать выполненные изменения в `CHANGELOG.md` и обновить статус в этом плане.
3. Сделать один или несколько точечных коммитов в `main` с префиксами `docs:`, `feat:`, `fix:` или `test:` по смыслу изменения.
4. Написать в чат результат, проверки, хеши коммитов и содержание следующего этапа.
5. Запросить продолжение и дождаться ответа пользователя. До ответа следующий этап не начинать.

Этот порядок задан пользователем. Коммит в локальную `main` и успешная публикация через GitHub Actions — разные результаты; о публикации сообщаем только после её проверки.

## План и критерии готовности

| Этап | Результат | Проверки | Статус |
| --- | --- | --- | --- |
| 1. Документация | Оформление в стиле SwiftUI, адаптивная схема процессора, план этапов и правила работы. | Сборка, ссылки, поиск, темы, клавиатурная навигация, мобильная вёрстка. | Готово |
| 2. Спецификация машины | Разрядность, регистры, размеры двух блоков памяти; фиксированные форматы инструкций, адресация, флаги; черновики двух программ. | Проверка достаточности команд для суммы и свёртки, ручные примеры кодирования и оценки диапазонов. | После продолжения |
| 3. Ядро CPU | Основа TypeScript-проекта, память команд и данных, регистры, кодирование/декодирование, АЛУ, `step()`, переходы, остановка и ошибки. | Семантика инструкций, независимость памяти, границы, знак, переносы, переполнение; ручная машинная программа. | Запланирован |
| 4. Ассемблер | Разбор текста и операндов, два прохода для меток, загрузка машинных слов, диагностика со строкой и причиной. | Прямые и обратные переходы, все способы адресации, неверные операнды, совпадение машинных кодов с ручными примерами. | Запланирован |
| 5. Интерфейс | React + Vite: редактор, сборка, шаг/запуск/пауза/сброс, регистры, флаги, поля инструкции и оба блока памяти. | Работа через единое ядро, одинаковые результаты шага и запуска, лимит команд, отзывчивость и понятные ошибки. | Запланирован |
| 6. Учебные программы | Сумма знакового массива и свёртка двух массивов по 10 элементов с многословным результатом. | Независимый эталон, отрицательные числа, смешанные знаки, расширение знака, переносы и результат шире двух слов. | Запланирован |
| 7. Отчёт и защита | Описание реализованной машины, обе программы на ассемблере и в машинных кодах, инструкция запуска и сценарий демонстрации. | Полный проход от чистой установки до обеих программ; соответствие отчёта коду и требованиям методички. | Запланирован |

Этапы можно уточнять по результатам работы. Следующий этап начинается только после сообщения пользователя о продолжении.

## Что уже определено

- Вариант 7: гарвардская архитектура, трёхадресные команды и знаковые целые в дополнительном коде.
- Стек эмулятора согласован пользователем: **TypeScript + React + Vite**, приложение работает в браузере.
- Длинная арифметика выполняется инструкциями эмулируемого процессора.
- Ядро, ассемблер и интерфейс разделены; один шаг исполняет одну машинную инструкцию.
- Сайт документации остаётся на VitePress. Его оформление вдохновлено SwiftUI: системная типографика, сгруппированные поверхности, синие акценты и две цветовые темы.

## Решения следующего этапа

На этапе 2 нужно определить разрядность данных и команды, число регистров, размеры и единицы адресации памяти, точный формат каждой инструкции, влияние операций на флаги и представление длинного результата. До этого параметры остаются предложениями из [README](../README.md), а не готовой спецификацией.

Код ядра и приложения будет добавлен на последующих этапах. Выбор стека не означает, что эмулятор уже реализован; текущие npm-команды запускают только сайт документации.

Распределение работы на троих описано в [разборе вариантов](variants.md). Состав бригады и дополнительные требования преподавателя остаются отдельными вопросами.
